# 更新・取得・同期の測定

リポジトリで `npm run benchmark -- 1000 3 20` を実行すると、端末ごとの初期キー数1000、端末数3、繰り返し20回で測定する。既定値も同じ。

実際の LocalStateStore を一時ディレクトリに作り、お気に入りの25%を削除情報として保存する。スナップショット取得、1キー更新、初回同期、変化のない反復同期について所要時間を測定し、p50/p95、保存バイト数、プロセスRSS、NodeとOSをJSON出力する。HTTPや実アプリのDB反映時間は含めない。

キー数・端末数を変えて測定し、アプリの想定データ量とディスクでも再確認する。閲覧位置等の高頻度操作はアプリ側でまとめ、終了前に未送信操作を保存・送信する。推奨間隔や最大規模は計測環境に依存するため、一律の性能保証は設けない。

現行は更新ごとに全端末文書を読み、自端末文書を保存する。削除情報は保持し続ける。削除情報の自動削除や件数上限は追加していない。実測結果をもとに、索引・差分読み取り・バッチ化を将来検討する。
